## 1. 웹소켓 배경지식

### 1.1 웹소켓이란?

WebSocket은 클라이언트와 서버 간의 양방향 실시간 통신을 가능하게 하는 통신 프로토콜입니다.
HTTP와 달리 연결이 지속되며, 서버에서 클라이언트로 능동적으로 데이터를 전송할 수 있습니다.

### 1.2 실시간 통신의 필요성

현대 웹 애플리케이션에서는 다음과 같은 실시간 기능들이 필수적입니다:

- **실시간 알림**: 주문 상태 변경, 메시지 수신 등
- **라이브 업데이트**: 주식 가격, 게임 스코어, 채팅 등
- **협업 도구**: 실시간 문서 편집, 화상 회의 등
- **모니터링**: 시스템 상태, 로그 스트리밍 등

### 1.3 HTTP vs WebSocket 비교

| 특성 | HTTP | WebSocket |
|------|------|-----------|
| **연결 방식** | 요청-응답 (단방향) | 양방향 지속 연결 |
| **오버헤드** | 매 요청마다 헤더 전송 | 초기 핸드셰이크 후 최소 오버헤드 |
| **실시간성** | 폴링 필요 (비효율적) | 즉시 전송 가능 |
| **서버 푸시** | 불가능 | 가능 |
| **상태 유지** | Stateless | Stateful |

### 1.4 WebSocket의 장점

- **낮은 지연시간**: 실시간 데이터 전송
- **효율적인 대역폭 사용**: 헤더 오버헤드 최소화
- **서버 푸시**: 클라이언트 요청 없이 데이터 전송 가능
- **양방향 통신**: 클라이언트와 서버 모두 메시지 전송 가능

### 1.5 WebSocket 사용 사례

- **채팅 애플리케이션**: 실시간 메시지 교환
- **게임**: 실시간 멀티플레이어 게임
- **금융**: 실시간 주식/암호화폐 가격 업데이트
- **IoT**: 센서 데이터 실시간 모니터링
- **협업 도구**: 실시간 문서 편집, 화이트보드

## 2. 디자인 컨셉

_마이크로서비스 환경에서 실시간 통신의 복잡성을 해결하기 위해 설계된 WebSocket 지원 서비스입니다._

### 2.1 API Gateway WebSocket API 개요

API Gateway WebSocket API와 Lambda를 결합한 서버리스 WebSocket 구현은 기존 서버 기반 WebSocket과 차별화된 특징을 제공합니다.

#### A. Lambda 기반 WebSocket의 핵심 특징

| 특징 | 기존 서버 방식 | Lambda + API Gateway |
|------|---------------|---------------------|
| **연결 관리** | 서버 메모리에 연결 상태 저장 | DynamoDB에 연결 정보 영구 저장 |
| **확장성** | 수동 스케일링 필요 | 자동 무한 확장 |
| **비용 구조** | 서버 운영 고정비 | 요청당 과금 (사용량 기반) |
| **가용성** | 단일 장애점 존재 | 다중 AZ 자동 분산 |
| **상태 관리** | 인메모리 상태 관리 | 외부 저장소 기반 상태 관리 |

#### B. Severless 기반의 WebSocket 장점

- **무제한 확장**: 동시 연결 수에 제한 없음
- **고가용성**: AWS 인프라의 99.99% 가용성 보장  
- **비용 효율성**: 실제 사용량에 따른 과금
- **운영 부담 제로**: 서버 관리, 패치, 모니터링 불필요

### 2.2 이벤트 기반 아키텍처 (Event-Driven Architecture)

서버리스 환경에서 완전한 이벤트 기반 아키텍처를 구축하여 마이크로서비스 간 느슨한 결합을 실현합니다.

#### A. 핵심 설계 원칙

| 목표 | 설명 | 이점 |
|------|------|------|
| **중앙집중식 통신** | 단일 WebSocket 서비스로 모든 실시간 통신 처리 | 운영 복잡성 감소, 일관된 통신 품질 |
| **이벤트 기반 통합** | SQS/SNS를 통한 비동기 이벤트 전달 | 서비스 간 느슨한 결합, 장애 격리 |
| **채널 기반 라우팅** | 도메인별 채널을 통한 선택적 메시지 수신 | 효율적인 대역폭 사용, 관심사 분리 |
| **상태 비저장** | DynamoDB 기반 연결 상태 관리 | 무제한 확장성, 고가용성 |

#### B. 이벤트 플로우

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│    Service A    │    │    Service B    │    │    Service C    │
└─────────────────┘    └─────────────────┘    └─────────────────┘
        |                       |                       |
        ▼                       ▼                       ▼
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│  Dynamo Stream  │    │  Dynamo Stream  │    │  Dynamo Stream  │
└─────────────────┘    └─────────────────┘    └─────────────────┘
        │                       │                       │
        └───────────────────────┼───────────────────────┘
                                ▼
                        ┌─────────────────┐
                        │     SQS/SNS     │
                        └─────────────────┘
                                │
                                ▼
                        ┌─────────────────┐
                        │  Socket Service │
                        └─────────────────┘
                                │
                ┌───────────────┼───────────────┐
                ▼               ▼               ▼
           Client 1         Client 2         Clien 3


1. 이벤트 발생
   [마이크로서비스] → 비즈니스 로직 실행

2. 이벤트 발행  
   [마이크로서비스] → [Dynamo Stream] → [SQS/SNS] (이벤트 메시지 발행)

3. 이벤트 수신
   [SQS/SNS] → [Socket service] (이벤트 메시지 수신 및 처리)

4. 채널 라우팅
   [Socket Service] → 채널별 구독자 식별

5. 실시간 전송
   [Socket Service] → [WebSocket 클라이언트] (실시간 메시지 전달)
```

#### C. 마이크로서비스 통합 이점

- **비즈니스 로직 집중**: 각 서비스는 도메인 로직에만 집중
- **기술 스택 독립성**: 서비스별 다른 기술 스택 사용 가능
- **배포 독립성**: 서비스별 독립적인 배포 및 확장
- **장애 격리**: 한 서비스 장애가 실시간 통신에 미치는 영향 최소화
- **개발 생산성**: 실시간 기능 개발 시간 단축

### 2.3 채널 구조

```
채널명: {service}:{modelType}
```

| 구성 요소 | 설명 | 예시 |
|-----------|------|------|
| **service** | 마이크로서비스 이름 | `lemon-orders-api` |
| **modelType** | 도메인 모델 타입 | `order`, `user`, `payment` |

#### 채널 예시

```
lemon-orders-api:order     → 주문 관련 이벤트
lemon-payment-api:payment  → 결제 관련 이벤트  
eureka-backend-api:user    → 유저 관련 이벤트
```
